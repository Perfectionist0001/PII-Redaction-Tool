# Ground Truth Annotation Guide

## 1. Overview & Purpose

This document establishes the official annotation guidelines for converting candidate entity detections into human-reviewed **Ground Truth** (`evaluation/ground_truth.json`). 

Automated candidate outputs (`evaluation/candidate_annotations.json`) generated by regular expressions and spaCy NER models contain candidate noise, multi-word span misalignments, and non-PII false positives. Human auditors must apply these guidelines when using `evaluation/review_annotations.py` to produce a verified evaluation benchmark.

### Ground Truth Lifecycle Workflow

```text
Candidate annotations
        ↓
Human review
        ↓
Accepted / rejected / corrected annotations
        ↓
Ground truth
        ↓
Evaluation
```

> [!CRITICAL]
> **Ground Truth Integrity Requirement**: Evaluation must NEVER use detector predictions as their own ground truth. Ground truth must only be described as "human verified" or "manually audited" if a human reviewer has explicitly performed line-by-line verification. When automated candidate rules are applied without human review, the output MUST be labeled as **Provisional Candidate Annotations**.

## 2. Category Definitions

| Category | Target Entity Description | Examples | Inclusion Criteria |
| :--- | :--- | :--- | :--- |
| **PERSON** | Names of natural persons | `Sarthak Malvadkar`, `Rajesh Kush`, `Prakash Boricha` | Individual executives, promoters, directors, compliance officers, and legal signatories. |
| **EMAIL** | Email addresses | `cs.connect@kshinternational.com`, `ksh.ipo@nuvama.com` | Standard `local@domain.ext` format for individuals or corporate contact channels. |
| **PHONE** | Fixed-line, mobile, fax numbers | `+91 20 6729 5100`, `+91 9876543210`, `022-68052182` | Formatted telecommunication numbers. |
| **ORGANIZATION** | Legal corporate entity names | `KSH International Limited`, `ICICI Securities Limited` | Private corporations, subsidiaries, registrars, auditors, and commercial banks. |
| **ADDRESS** | Physical/mailing postal addresses | `11/3, Village Birdewadi, Chakan, Pune – 410501` | Multi-component physical addresses (premise + locality + city/state + PIN). |
| **SSN** | US Social Security Numbers | `123-45-6789` | Standard 9-digit hyphenated format `NNN-NN-NNNN` (absent in Indian prospectuses). |
| **CREDIT_CARD** | Financial card numbers | `4111 1111 1111 1111` | 13–19 digit valid Luhn checksum card numbers. |
| **DOB** | Dates of birth of natural persons | `15/08/1998`, `Date of Birth: 15 August 1998` | Dates explicitly associated with an individual's birth. |
| **IP_ADDRESS** | IPv4 / IPv6 network addresses | `192.168.1.1`, `10.0.0.1` | Valid dotted decimal IPv4 or IPv6 network addresses. |

## 3. Project-Specific Annotation Rules

Auditors must strictly enforce the following 8 annotation rules during review:

### Rule 1: Do Not Classify Every Date as DOB
* **Policy**: Prospectus filing dates (`"Dated December 10, 2025"`), corporate incorporation dates (`"incorporated on July 30, 1979"`), financial period end dates (`"March 31, 2023"`), and agreement signing dates are **NOT** DOBs.
* **Action**: Reject any date candidate that lacks an explicit birth contextual trigger (*"Date of Birth"*, *"DOB"*, *"Born on"*).

### Rule 2: Do Not Classify Every Number as PII
* **Policy**: Ordinary numbers, share counts (`26,704,570`), transaction volumes, percentage statistics (`47.00%`), and serial numbers are **NOT** PII.
* **Action**: Reject numeric candidates that do not represent validated phone numbers, credit cards, or SSNs.

### Rule 3: Do Not Classify PAN Keyword References as PAN Values
* **Policy**: Generic text references to the word *"PAN"* (e.g. *"PAN number"*, *"PAN India"*, *"PAN details"*) are **NOT** PII values.
* **Action**: Reject candidate matches for the standalone word "PAN". Only accept exact 10-character alphanumeric Indian Tax ID strings matching `[A-Z]{5}[0-9]{4}[A-Z]`.

### Rule 4: Do Not Classify Page Numbers as PII
* **Policy**: Page numbers, page index references (e.g. *"page 398"*, *"on page 417"*), and header running page counts are **NOT** PII.
* **Action**: Reject all page number candidates.

### Rule 5: Do Not Classify Financial Figures as PII
* **Policy**: Monetary figures (e.g. *"₹ 50,00,000"*, *"₹ 150.50 Million"*), issue prices, asset valuations, and financial statement numbers are **NOT** PII.
* **Action**: Reject all financial figures.

### Rule 6: Do Not Classify Company Registration Numbers as SSNs
* **Policy**: Corporate Identity Numbers (CIN e.g. `U28129PN1979PLC141032`), RoC registration codes (`080618`), and SEBI registration IDs (`INM000010950`) are **NOT** US Social Security Numbers.
* **Action**: Reject company registration numbers tagged as SSNs.

### Rule 7: Organization / Company Detection Scope
* **Policy**: Organization and company name detection is explicitly required by the assignment scope, even though corporate entities are not inherently natural person PII.
* **Action**: Accept private corporate entity names (`ORGANIZATION`) such as issuers, lead managers, underwriters, auditors, and registrars.

### Rule 8: Public Organization Policy
* **Policy**: Standard public regulatory authorities, government bodies, statutory institutions, and stock exchanges (e.g. *"SEBI"*, *"Securities and Exchange Board of India"*, *"Reserve Bank of India"*, *"RoC"*, *"BSE Limited"*, *"NSE"*) are public regulatory entities rather than private confidential PII.
* **Action**: In ground truth annotation, exclude public regulatory bodies to focus ground truth on private corporate entities and individual PII, or mark regulatory bodies with lower priority.

### Rule 9: Generic Term Policy
* **Policy**: The prospectus contains many generic words that should **NOT** be treated as `PERSON` or `ORGANIZATION` unless the context clearly indicates that they are part of actual entity names. Generic terms to reject include:
  - `Offer`, `Company`, `Directors`, `Promoters`, `Bidders`, `Board`
  - `Registered Office`, `Corporate Office`
* **Action**: Reject generic noun candidates. Do **NOT** automatically reject legitimate corporate names such as `KSH International Limited`, `ICICI Securities Limited`, or `Nuvama Wealth Management Limited`. Use context and legal-entity naming identifiers (e.g., "Limited", "PLC") to verify.

## 4. Reviewer CLI Workflow Instructions

The Python utility `evaluation/review_annotations.py` enables human review:

1. **Start Interactive CLI Audit**:
   ```bash
   python evaluation/review_annotations.py --interactive
   ```
2. **Review Candidates**:
   - `a` — **Accept** candidate as valid PII (sets `review_status: human_verified`).
   - `r` — **Reject** candidate as a false positive (excludes from ground truth).
   - `c` — **Change Entity Type** (sets `review_status: human_modified_type`).
   - `e` — **Edit Span / Text** (sets `review_status: human_corrected_span`).
   - `m` — **Add Missing Entity** (sets `review_status: human_added_manually`).
   - `s` — **Skip** candidate (present again next session).
   - `q` — **Quit** (saves progress to `evaluation/ground_truth_verified.json`).
3. **Generate Final Ground Truth**:
   The utility writes verified human-reviewed annotations to `evaluation/ground_truth_verified.json`. If incomplete, the file is marked as `PARTIALLY HUMAN REVIEWED`. When all candidates are reviewed, the file status becomes `HUMAN VERIFIED GROUND TRUTH`.
